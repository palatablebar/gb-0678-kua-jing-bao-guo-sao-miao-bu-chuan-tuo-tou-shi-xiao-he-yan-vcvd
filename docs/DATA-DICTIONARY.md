# 扫描时效定义

scan_id是扫描事件唯一键，parcel是包裹号。节点按收件、起运、清关、妥投顺序推进；可缺中间节点，但必须有收件。按event_time排序，received_time仅用于上传延迟。倒退扫描隔离，不改写先前妥投事件。妥投使用最早有效发生时刻。

## 节点代码口径版本（承运商本月改义）

节点原始代码不再按单一字典解释，而由 `app/node_policy.py` 的版本化注册表裁决：

- v2026-10（旧版，切换时刻 2026-11-10T00:00:00Z 前有效）：原始代码 CN = 清关 CUSTOMS。
- v2026-11（新版，切换时刻起有效）：同一代码 CN 改义为起运 DEPART。
- 中文别名（收件/起运/清关/妥投）与英文标准节点在两套口径下含义不变。
- 适用锚点是每条扫描的**事件发生时刻（event_time 转 UTC）所在生效窗口**，不是补传/上传时刻。旧扫描即使在切换后补传，仍命中旧口径，原路径依据不会被重排。
- 每条扫描同时保留两套口径的解释（node_interpretations）；按时刻命中的为 anchor，另一套为 alternative。
- 路径阶段逐票先按 anchor 解释重建路径；若出现倒退/同刻冲突/缺收件，则对改义代码逐条尝试 alternative 解释，第一个使整票路径有效的方案胜出，结果标记 node_policy_result=fallback 并写明回退细节；所有口径都无效时问题扫描隔离（NODE_POLICY_NO_VALID_PATH），有效前缀仍出正式路径，隔离记录附带每个候选方案的路径与失败原因。
- 参数 node_policy 可选 event_time（默认，按事件时刻）、force_legacy（整批强制旧版）、force_current（整批强制新版，不回退）；node_cutover 可覆盖切换时刻。强制口径失败计入 forced_policy_failures。
- 清单记录口径注册表指纹 node_registry_fingerprint、切换时刻与本批模式；归档证据 CSV 为每条扫描保留原始代码、锚点版本、采用版本、是否回退覆盖（overridden）及备选解释，旧批次载荷按封存内容回放，规则升级不改变已归档结论。

目的地JP/US/DE对应东京/纽约/柏林。时效以目的地工作日小时计算，周末与节假日停表。JP含2026-11-03与11-23，US含11-26，DE含10-03；支持按参数覆盖假日。未妥投计算至as_of，默认2026-11-18T00:00Z。每超时小时赔付1元，上限保价10%，reported为原申报赔付。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。
